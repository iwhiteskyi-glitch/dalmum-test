# 꿈해몽(/dream) 작성 규칙

운세·궁합·관상 작업에서 나온 피드백을 전부 반영해서, 이번에는 처음부터 수정이 적게 가도록
만들기 위한 체크리스트. (docs/는 git 미포함, 로컬 전용 — 다른 코너와 동일한 관례.)

## 1. 이 코너만의 특징 — 엔진 재사용이 안 됨
- 닮았네(얼굴 인식)·사주(절기 계산) 같은 재사용 가능한 수학이 없음. 사용자가 "꿈에 나온
  요소"를 직접 골라서 선택하는 방식(체크박스/칩 선택) — 사진도 생년월일도 입력하지 않음.
- 대신 **관상의 "종합 보기" 패턴**(이미 알려진 카테고리 두 축을 조합해 작은 표를 손으로
  쓰는 방식)을 재사용: 선택한 상징들의 길흉 태그(좋은 흐름/무난한 흐름/조심할 흐름) 중
  "좋은 흐름이 있는가" × "조심할 흐름이 있는가" 2×2 = 4가지 조합만 종합 문구로 손으로
  써서 커버. 선택 개수나 조합이 몇 개든(최대 6개) 새 조합을 만들어내지 않음.

## 2. 콘텐츠 안전 — 이 코너에서 특히 중요한 규칙
- **전통 민담의 불길한 통설(가족의 사고·질병·죽음과 연결 짓는 해석)은 절대 쓰지 않는다.**
  예: 이가 빠지는 꿈의 전통 통설(가족의 불행)은 절대 언급 금지 — 현대적·심리적 순화 해석
  (걱정 정리, 변화의 신호)만 사용.
- ~~"죽음" 자체를 상징으로 다루지 않는다.~~ **(v1 한정 — v2부터 사용자 결정으로 "죽는 꿈"을
  포함하되 §7의 엄격 규칙 아래에서만 허용)**
- 피·다침·쫓김처럼 긴장되는 이미지가 나오는 꿈도 **문구 자체는 안심시키는 톤**으로 마무리
  (예: "나쁜 징조로 보지 않아도 돼요").
- 모든 해석 끝에는 재미 목적 디스클레이머가 있어 "운명 예언이 아니다"가 분명해야 함
  (관상 디스클레이머와 같은 톤 — "전통 해몽을 바탕으로 재미로 보는 풀이", 확정적 단언 금지).
- 성별·외모 평가로 읽힐 수 있는 표현 금지(관상에서 확립된 규칙, 여기도 동일 적용).

## 3. 공유·개인정보
- 선택한 상징은 사진·생년월일처럼 민감하지 않지만, 그래도 같은 원칙 유지: 서버에 저장하지
  않고 브라우저에서만 처리. 공유 링크에는 선택한 상징의 id만 담음(`#d1.id-id-id`).
- 공유 카드(이미지)·링크 복사 3중 구조를 처음부터 구현(운세·궁합·관상에서 확립된 패턴).

## 4. 화면·스타일 재사용
- 결과 화면 레이아웃은 `components/fortune/fortune.module.css`의 공용 클래스(.block,
  .cta, .shareRow, .disclaimer, .nextCard 등)를 그대로 쓰고, 테마만 `.dreamTheme` 추가.
- 선택 화면(카테고리 탭 + 칩 선택)만 `components/dream/dream.module.css`로 별도 작성.
- 모바일 헤더 탭은 이미 가로 스크롤 처리돼 있어 코너가 하나 늘어도 추가 수정 불필요(관상
  때 고친 `components/site.module.css` 로직이 코너 수에 무관하게 동작).

## 5. 공개 준비 체크리스트 — 기능 구현과 동시에
- OG 이미지, 정책 페이지(개인정보처리방침/이용약관/FAQ/소개) 갱신, sitemap 등록을 커밋마다
  같이 진행(맨 마지막에 몰아서 하지 않음). noindex 해제만 공개 게이트 직전 마지막 커밋으로
  남겨둠.
- EN 버전 만들지 않음(이미 전면 제거됨, 재추가 금지).

## 6. 검토
- 콘텐츠(상징 해석 36개 + 종합 4개)는 독립 검토자 2명에게 동시에 보여주고, 둘 중 하나라도
  지적한 내용은 전부 반영(기존 방식과 동일).
- 자동 충돌 검사(고정 틀 제외하고 5자 이상 중복 탐지)도 동일하게 돌림.

## 7. "죽는 꿈" 및 민감 상징 — 일반 상징보다 엄격하게
대상: 죽는 꿈(death). 이후 추가될 시체·장례식·귀신·사고·임신·출산·바람피우는 꿈도 같은 수준.
- **꿈이 실제 죽음·사고를 예고한다는 뜻으로 읽힐 문장은 한 줄도 쓰지 않는다.** "누가 아플
  수 있다", "조심하라는 경고" 같은 표현도 금지.
- 전통 해몽의 실제 통설(죽는 꿈 = 묵은 것이 끝나고 새로 시작하는 길몽)을 중심으로 쓰되,
  "길몽이니 좋은 일이 생긴다"고 단정하지 않는다.
- **최근 실제로 누군가를 잃은 사람을 위한 문단을 반드시 둔다.** 그런 경우 꿈은 해몽보다
  마음이 슬픔을 정리하는 과정으로 보는 게 자연스럽다고, 해석을 강요하지 않는 톤으로.
  상담·치료를 권하는 의료적 조언 형태로는 쓰지 않는다.
- 묘사는 담백하게: 피·시신의 모습·사고 장면을 구체적으로 그리지 않는다.
- 임신·출산(태몽) 계열을 다룰 때: **태아 성별 예측 금지**(전통 태몽의 "아들/딸" 통설은 쓰지
  않음), 실제 임신 여부를 암시하지 않음.
- **(샘플 검토 반영)** 민감 상징은 symbols.json에 `"sensitive": true`. 화면이 자동으로
  ① 길흉 배지를 숨기고 ② care 문단을 요약 바로 아래(가장 먼저 보이는 곳)에 둠. 민감 상징의
  luck은 1(무난한 흐름)로 — 종합 흐름 계산에서 "좋은 기운이 많아요"가 뜨지 않게.
  현재 민감 상징: death, ancestor(돌아가신 분 꿈 — 사별한 사람이 가장 많이 볼 상징).
- care 문단은 "이별"이 아니라 "떠나보냈다면"처럼 사별이 분명한 말로. "~로 보는 편이 더
  맞아요"처럼 독자를 바로잡는 말투 금지.
- **자해·자살 맥락에서 읽힐 수 있는 연결 금지:** "내가 죽는 꿈 → 고민을 내려놓는다 / 벗어난다 /
  편해진다"처럼 죽음과 해방감을 잇는 표현 쓰지 않음. 변화는 "역할·생활 방식이 바뀐다"처럼
  생활 범위로 좁혀서.
- **(사용자 결정 2026-10-03)** 죽음 관련 페이지에는 `pages.json`의 `helpline` 필드로
  자살예방 상담전화(109) 안내를 둠. "109는 24시간 무료"처럼 사실만 안내하고, "상담을
  받으세요"식 권유 어투는 쓰지 않음(§8 의료 권고 금지의 유일한 예외 — 치료·진단 권유는
  여전히 금지). 화면 템플릿이 "요즘 식으로 보면" 섹션 끝에 자동으로 붙임. death에 적용,
  앞으로 추가될 시체·사고 등 비슷한 수준의 민감 상징에도 같은 필드 사용.
- "가족이 죽는 꿈"의 행동 제안은 "확인해 봐라"(불안을 인정)가 아니라 "반가운 마음으로 연락해
  봐도"(연결의 계기)로.
- 통설이 금지 대상인 꿈(예: 이빨 빠지는 꿈)은 순화한 풀이를 "전통 해몽"이라고 부르지 않음 —
  전통을 지어내는 셈. pages.json의 `meaningTitle`로 섹션 제목을 "~, 어떻게 볼까" 식으로 바꾸고
  본문은 "흔히 ~로 읽어요"로. 이런 꿈은 "조심할 흐름" 배지도 통설을 떠올리게 하므로 luck 1.
- 메타 설명이나 본문에 "무섭지 않게", "불길하다고들 하지만"처럼 원래 무서운 꿈이라는 전제를
  까는 말 금지. "실제로 무슨 일이 생길까 걱정할 필요 없어요"도 공포를 불러내므로 금지 —
  "꿈은 요즘의 마음을 비춰 줄 뿐이에요"처럼 긍정형으로.

## 8. 상세 페이지 작성 규칙
- 구성: 요약(1문장) / 전통 해몽에서의 의미(1문단) / 상황별 풀이 4~7개 / 요즘 식으로 보면
  (1문단) / 비슷한 꿈. 본문 합계 1,200~1,800자. (최초 4~6개로 정했으나 0단계 확장 작업 중
  분량 확보와 검색어 커버리지를 위해 7개까지 허용 — scripts/dream/check-pages.mjs도 동일)
- **상황별 풀이는 사람들이 실제로 검색할 만한 장면 단위로**(예: "뱀에게 물리는 꿈",
  "흰 뱀이 나오는 꿈"). 각 상황은 2~3문장, 다른 상황과 실질적으로 다른 내용이어야 함 —
  "~하면 재물운, ~해도 재물운"처럼 결론만 같은 반복 금지.
- **상황별 풀이에도 길흉 단정 금지 규칙 그대로 적용.** 조심할 장면도 안심 문장으로 마무리.
- **출처를 지어내지 않는다.** "○○ 해몽서에 따르면", "옛 문헌에", "연구에 따르면",
  특정 학자·책 이름 금지. 쓸 수 있는 표현은 "전통 해몽에서는", "흔히", "예부터" 정도.
- **"요즘 식으로 보면"은 심리 진단이 아니다.** "스트레스 장애", "불안증" 같은 진단명,
  "전문가 상담을 받으세요" 같은 의료 권고 금지. 생활 속 마음 상태 정도로만.
- 짧은 해석(symbols.json의 text)과 상세 페이지 문장이 그대로 겹치지 않게 — 상세 페이지는
  짧은 해석을 늘려 쓴 게 아니라 새로 쓴 글이어야 함.
- 페이지끼리 같은 문장·같은 문단 구조 반복 금지(자동 생성 저품질 판정 방지). 자동 중복
  검사 스크립트로 페이지 간 겹침 확인.
- 모든 페이지 마지막에 디스클레이머(화면 템플릿이 자동으로 붙임 — 본문에 중복해서 쓰지 않음).

### 8-1. 틀에 찍은 글처럼 보이지 않게 (샘플 검토에서 두 검토자 모두 가장 크게 지적)
- **상황 문단의 결론이 서로 달라야 함.** 예: 뱀꿈 — 물리는 꿈=재물/수입, 쫓아오는 꿈=피하던
  일이 사실 필요한 일, 흰 뱀=귀인, 구렁이=집안 단위의 복, 잡거나 죽이는 꿈=골칫거리 매듭.
  6개가 전부 "기회·기운이 들어온다"로 모이면 실패.
- **상황 문단 시작을 섞어 씀:** 장면 묘사형("금빛으로 번쩍이는 뱀은…"), 감정 공감형("물리는
  순간은 아찔했겠지만…"), 대조형("빠지지 않고 흔들리기만 하는 꿈은 이야기가 조금 달라요"),
  통설 소개형("예부터 흰 뱀은…"), 질문형("~한 자리가 있었나요?").
- **동사 분산:** "풀이해요"는 페이지당 4회 이하 — 봐요/읽어요/여겨요/이야기해요로 나눠 씀.
- **"~했다면" 조건문은 페이지당 4회 이하.**
- "요즘 식으로 보면" 섹션 본문을 "요즘 식으로 보면,"으로 시작하지 않음(제목 반복). 끝맺음도
  페이지마다 다르게: 생활 팁, 적어 보기 제안, 질문, 안심 문장 등을 돌려 씀.
- 메타 설명도 "X 해몽: A, B, C까지 ~풀어 드려요" 한 틀로 고정하지 않음 — 질문형·안심형·
  나열형을 섞고, 실제 검색어 그대로("뱀에게 물리는 꿈") 넣음.
- **검색이 많은 세부 장면을 빠뜨리지 않음**(예: 이빨 빠지는 꿈의 "피가 나는", "한꺼번에
  빠지는"). 단 안전 규칙상 뺀 장면은 계속 뺌: 윗니/아랫니(윗사람·아랫사람 통설), 뱀꿈 태몽,
  자식이 죽는 꿈, 누군가를 죽이는 꿈.
- 앞으로 별도 페이지가 될 상징(예: 장례식, 시체)은 다른 페이지의 상황 항목으로 넣지 않음 —
  같은 검색어로 우리 페이지끼리 경쟁하게 됨.
- 위 빈도·끝맺음·페이지 간 10자 이상 겹침은 scripts/dream/check-pages.mjs가 자동 검사.

## 9. 상징 추가 규칙(2~3단계)
- 고르는 순서: 많이 찾는 꿈 → 덜 찾는 꿈. 카테고리 균형은 신경 쓰지 않음.
- id는 영어 소문자 한 단어(또는 하이픈 없는 합성어). **한번 정한 id는 바꾸지 않음**(공유
  링크·페이지 주소가 깨짐).
- 새 상징은 symbols.json(짧은 해석) + pages.json(상세 페이지) + select.js의 SYMBOL_IDS에
  함께 추가. check-symbols.mjs가 셋이 어긋나는지 검사.
